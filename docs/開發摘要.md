# 開發摘要（2026-10-08 更新）

AMR SLAM 模擬與任務派送系統。本文件整理目前為止的需求、決策與進度。子專案 1 已於 Ubuntu 22.04 實機上從零重建並歸檔；子專案 2（建圖／定位／導航）完成（逐步學習筆記見 `docs/學習筆記/`）。

---

## 1. 專案目標

1. 一張 3D 地圖（之後可編輯、新增）
2. 可在 Gazebo 顯示（3D 視角可旋轉）
3. 模擬車輛掃圖建地圖
4. 模擬車輛 SLAM 定位
5. 在掃出的地圖上設定儲位
6. 前端圖形介面：顯示車輛目前位置、指定車輛前往某點
7. 前端任務佇列系統

## 2. 已定案的決策

| 主題 | 決策 |
|---|---|
| 執行環境 | **Ubuntu 22.04 實機** + 原生 Docker Engine + NVIDIA Container Toolkit（RTX 3060 Mobile、驅動 580-open、GNOME on Xorg） |
| 系統分層 | **世界（sim 容器）與車子系統（robot 容器）分開**；車子系統中控依 `hardware: sim\|real` 帶起虛擬（Gazebo）或真實驅動，兩者提供相同 topic；真車只部署 robot 側 |
| ROS / 模擬器 | ROS 2 Humble + **Gazebo Fortress**（`ros_gz`）；不用 Gazebo Classic（2025/1 已 EOL） |
| 多車 | 先做一台，架構預留多台：所有 topic／TF frame／Nav2 都帶 namespace（第一台 `amr1`），API 皆帶 `robot_id` |
| 地圖編輯 | ① YAML 場景描述 → SDF 產生器（結構變更）② Gazebo GUI 微調後另存 `<name>_edited.sdf`（細節）。traffic-editor 之後視需要再導入 |
| SLAM | 第一版 **2D：slam_toolbox + Nav2**；3D SLAM（RTAB-Map + 3D 光達）列為之後獨立子專案 |
| 後端 | FastAPI + rclpy + SQLite；負責儲位、任務佇列、派車，WebSocket 推即時位置 |
| 前端 | React + Vite + TypeScript；**只與後端溝通，不直連 ROS**；2D／3D 切換（react-three-fiber），3D 先用「2D 佔據格拉高」呈現 |
| 任務 | 單點任務 `[前往 X]` 與取放貨任務 `[前往 A → 停留 → 前往 B → 停留]`；支援取消／暫停；導航失敗 → 標記失敗、跳提醒，由操作者選「停止佇列」或「下一個」 |
| 儲位 | 在前端地圖上點選位置＋拖曳朝向、命名；綁定所屬地圖 |
| 規格管理 | OpenSpec（`openspec/`），文件以繁體中文撰寫；每個子專案一個 change |
| Git | `.gitattributes` 強制 LF（`* text=auto eol=lf`），png/jpg/pgm/stl/dae 標為 binary |
| 學習 | 每一步寫學習筆記（為什麼／做了什麼／怎麼驗證／面試追問／踩坑紀錄） |

## 4. 子專案 1 內容

```
docker/amr_sim/          Dockerfile、entrypoint、compose（sim／robot 兩個 service）、軟體渲染疊加檔、
                         build.sh、up.sh <gpu|cpu> <sim|robot|all>、exec.sh <sim|robot>、config/ros.env
ros_ws/src/
  amr_worlds/            場景 YAML → SDF 產生器、warehouse_small、world.launch.xml（Gazebo + /clock）
  amr_description/       差速 AMR xacro（兩驅動輪 + 剛性支撐球、gpu_lidar、IMU、Fortress 外掛）
  amr_bringup/           車子系統中控 robot.launch.xml（不依賴任何模擬套件）
  amr_hw_sim/            虛擬驅動 sim_hardware.launch.xml（spawn、cmd_vel_watchdog、底盤／光達／IMU bridge）、冒煙測試
```

測試：`colcon test` 共 117 個（amr_worlds 49、amr_description 25 + 1、amr_bringup 9、amr_hw_sim 33 含 launch_testing 冒煙測試），全部通過。

### 實測重點

- 容器內 OpenGL renderer 為 RTX 3060；軟體渲染疊加檔為 llvmpipe。
- scan 10 Hz、odom 29.4 Hz、imu 100 Hz、joint_states 1000 Hz（Fortress 每個物理步發布，無頻率參數）。
- 停送指令後 0.86 s 停車（watchdog 0.5 s + 減速 1.0／2.5）；超速指令截斷在 1.0 m/s。
- 出生點 (1, 1) 時光達後方 1.150 m、右方 1.000 m，與幾何吻合。
- 兩個容器的 `ROS_DOMAIN_ID` 一致時互通，不同 domain 互相看不到。

### 與原始規劃的出入（已回寫 OpenSpec）

- 2026-10-08 架構調整：世界與車子系統分離、硬體模式、移除 `AMR_WORLDS_DIR`。
- 2026-10-08 launch 改為 XML（使用者要求，較接近 ROS 1）：設定改為 launch 參數，刪除 `world.yaml`／`robot.yaml` 與三層合併程式、`bridge.py`；出生點以 `x:=`／`y:=`／`yaw:=` 指定（筆記 14）。
- 車子系統重新啟動時，既有車輛「停下並以 set_pose 移回出生點」而非「移除再生成」：Fortress 移除同時帶 gpu_lidar 與 IMU 的模型後場景服務會損壞。
- spawn 以 `-string` 傳 URDF（`-file` 跨容器讀不到）。
- watchdog 結束時直接以 `ign topic` 送零速度（經 bridge 會因 bridge 先結束而送不到）。
- 移除 flake8／copyright／pep257 等 lint 測試（使用者決定；ament_flake8 的外掛也未安裝）。

測試：`colcon test` 171 個全部通過（導航冒煙測試用使用者建的 `warehouse_small`；整合測試在 robot 容器執行）。

### 決策與發現

- 參數檔以 `<param from=... allow_substs="true"/>` 代換 `$(var robot_id)`，節點鍵寫完整名稱才套得到 costmap 子節點（筆記 15）。
- `use_sim_time` 用 `ros_args="-p use_sim_time:=..."`（程序層級）；`<param>` 套不到 costmap 子節點（筆記 19）。
- `map` 座標系原點＝開始建圖時車的位置；掃完後用「標地圖原點」（`map_origin_ui.launch.xml`）把原點標在倉庫的固定參考點，地圖座標＝倉庫座標。repo 的 `warehouse_small` 原點在倉庫左下角（＝ Gazebo 世界座標）。
- **車輛模型修正**：驅動輪碰撞改為球形。圓柱的接觸點在輪緣，有效輪距 0.40 m（參數 0.44），原地旋轉多轉 10%，odom 漂移、SLAM 地圖扭曲（筆記 17）。
- planner `tolerance: 0`：官方 0.5 會把障礙物內的目標換成附近替代點並回報成功（實測停在 0.59 m 外卻 SUCCEEDED）。
- RViz 用內建 2D Pose Estimate／2D Goal Pose 並把 topic 改成 `/amr1/...`；Nav2 的 RViz 外掛在 Humble 不支援 namespace。
- 建圖 GUI 做成 RViz 面板外掛（使用者要求）：呼叫 Nav2 `map_saver_server` 的 `/amr1/map_saver/save_map`；slam_toolbox 自帶面板寫死 `/slam_toolbox/save_map` 不支援 namespace。開始／停止建圖按鈕先不做（筆記 22）。
- 冒煙測試的關閉檢查：所有程序同時關閉時 Gazebo 偶爾卡死被 SIGKILL、parameter_bridge 偶爾 segfault（上游模擬工具），這兩類只印警告；其他程序仍須正常結束。

## 6. 渲染／GPU 的技術結論

- **一律使用 ogre2**。ogre1 下光達全部回報 0.12 m。
- 容器不裝驅動：NVIDIA Container Toolkit（CDI）在啟動時注入與主機一致的驅動函式庫；雙顯卡以 `__NV_PRIME_RENDER_OFFLOAD=1`、`__GLX_VENDOR_LIBRARY_NAME=nvidia` 指定 NVIDIA。
- 無 GUI 模式以 `-s --headless-rendering`（EGL）離屏渲染，光達照常運作。

## 7. 常用指令

```bash
docker/amr_sim/build.sh                     # 建置映像
docker/amr_sim/up.sh gpu all                # 啟動兩個容器（cpu：軟體渲染；sim／robot：只啟動一個）
docker/amr_sim/exec.sh sim                  # 世界
ros2 launch amr_worlds world.launch.xml
docker/amr_sim/exec.sh robot                # 車子系統
ros2 launch amr_bringup robot.launch.xml hardware:=sim x:=1 y:=1
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r cmd_vel:=/amr1/cmd_vel
ros2 launch amr_bringup robot.launch.xml hardware:=sim x:=1 y:=1 mode:=navigation map:=warehouse_small
ros2 launch amr_rviz_plugins mapping_ui.launch.xml use_sim_time:=true   # 建圖 + RViz 建圖面板
ros2 run nav2_map_server map_saver_cli -f /data/maps/NAME --ros-args -r map:=/amr1/map -p use_sim_time:=true
ros2 run amr_worlds gen_world /ros_ws/src/amr_worlds/scenes/warehouse_small.yaml
cd /ros_ws && colcon test && colcon test-result --verbose   # robot 容器內
```
