# 開發摘要（2026-10-06）

AMR SLAM 模擬與任務派送系統。本文件整理目前為止的需求、決策與進度，供轉移到 **Ubuntu 22.04 實機（雙系統）** 後接續開發。

---

## 1. 專案目標

1. 一張 3D 地圖（之後可編輯、新增）
2. 可在 Gazebo 顯示（3D 視角可旋轉）
3. 模擬車輛掃圖建地圖
4. 模擬車輛 SLAM 定位
5. 在掃出的地圖上設定儲位
6. 前端圖形介面：顯示車輛目前位置、指定車輛前往某點
7. 前端任務佇列系統

## 2. 已定案的決策

| 主題 | 決策 |
|---|---|
| 執行環境 | **Ubuntu 22.04 實機（雙系統）+ 原生 Docker Engine**；直接在 Ubuntu 開發 |
| ROS / 模擬器 | ROS 2 Humble + **Gazebo Fortress**（`ros_gz`）；不用 Gazebo Classic（2025/1 已 EOL） |
| 多車 | 先做一台，架構預留多台：所有 topic／TF frame／Nav2 都帶 namespace（第一台 `amr1`），API 皆帶 `robot_id` |
| 地圖編輯 | ① YAML 場景描述 → SDF 產生器（結構變更）② Gazebo GUI 微調後另存 `<name>_edited.sdf`（細節）。traffic-editor 之後視需要再導入 |
| SLAM | 第一版 **2D：slam_toolbox + Nav2**；3D SLAM（RTAB-Map + 3D 光達）列為之後獨立子專案 |
| 後端 | FastAPI + rclpy + SQLite；負責儲位、任務佇列、派車，WebSocket 推即時位置 |
| 前端 | React + Vite + TypeScript；**只與後端溝通，不直連 ROS**；2D／3D 切換（react-three-fiber），3D 先用「2D 佔據格拉高」呈現 |
| 任務 | 單點任務 `[前往 X]` 與取放貨任務 `[前往 A → 停留 → 前往 B → 停留]`；支援取消／暫停；導航失敗 → 標記失敗、跳提醒，由操作者選「停止佇列」或「下一個」 |
| 儲位 | 在前端地圖上點選位置＋拖曳朝向、命名；綁定所屬地圖 |
| 規格管理 | OpenSpec（`openspec/`），文件以繁體中文撰寫；每個子專案一個 change |
| Git | `.gitattributes` 強制 LF（`* text=auto eol=lf`） |

## 4. 子專案 1 目前實作內容

```
compose.yaml                 # 根目錄入口：include docker/compose.yaml → `docker compose up sim`
docker/
  ros.Dockerfile             # osrf/ros:humble-desktop + ros-gz、nav2、slam_toolbox、xacro、pytest…（約 5.6 GB）
  compose.yaml               # sim service：host 網路、標準 X11（DISPLAY + /tmp/.X11-unix）、掛載 ros_ws
  compose.gpu-wsl.yaml       # WSL 專用 GPU 疊加檔（轉到實機後不再需要，見第 6 節）
  entrypoint.sh              # source ROS；首次或 BUILD=1 時 colcon build --symlink-install
  .env                       # ROS_DOMAIN_ID、WORLD、SIM_SOFTWARE_RENDER

  amr_worlds/                # 場景產生器 gen_world（21 個 pytest）、scenes/warehouse_small.yaml、worlds/*.sdf
  amr_description/           # amr.urdf.xacro：差速底盤、2D gpu_lidar、IMU、Fortress 外掛
  amr_bringup/               # sim.launch.py、ros_gz_bridge 設定、cmd_vel_watchdog（7 個 pytest）
```

### 已驗證（在 WSL 上實測）

- Gazebo Fortress 6.18；Gazebo 視窗顯示倉庫與車、可旋轉
- 場景產生器：驗證錯誤時不寫檔、輸出可重現
- topic：`/amr1/{cmd_vel, odom, scan, imu, joint_states}`、`/tf`、`/tf_static`、`/clock`；無未帶 namespace 的車輛 topic
- 頻率：scan 10 Hz、odom ~30 Hz、imu 100 Hz；RTF ≈ 1.0
- 速度上限：下 5.0 m/s、9.0 rad/s → 實際 1.0 / 1.5；停送指令 0.5 s 後停車（watchdog）
- 出生位姿 (1, 1, 0)；光達量測與幾何吻合（前 10.75 m、右 1.0 m、後 1.15 m）

### 與 OpenSpec 規劃的出入（需回寫 design／tasks）

- 產生器位置：`amr_worlds/gen_world.py`（`ros2 run amr_worlds gen_world`），不是 `scripts/gen_world.py`
- Fortress 外掛名稱為 `ignition-gazebo-*`、frame 用 `<ignition_frame_id>`（design 寫的 `gz-sim-*` 是 Garden 以後的名稱）
- 新增根目錄 `compose.yaml`（include）
- 出生點驗證多一條：與任何元素保持 0.35 m 距離
- 世界與場景由原始碼目錄讀取（`AMR_WORLDS_DIR`、`AMR_SCENES_DIR`），改 YAML 不需重新 build

## 5. 渲染／GPU 的技術結論

- **一律使用 ogre2**。ogre1 實測光達全部回報 0.12 m（量不到環境），不可用。
- 預設 compose 為軟體渲染（`LIBGL_ALWAYS_SOFTWARE=1`、`MESA_GL_VERSION_OVERRIDE=3.3`），在任何 Linux 都能跑，模擬本身接近即時，GUI 較卡。
- WSL 上的 GPU 問題（Mesa d3d12 只回報 OpenGL 4.2、缺 `GL_ARB_copy_image` → ogre2 崩潰，需假報版本）**在實機 Ubuntu + NVIDIA 原生驅動下不存在**。

## 6. 轉到 Ubuntu 實機後要做的事

### 6.1 主機準備

1. 安裝 Ubuntu 22.04（雙系統）與 **NVIDIA 專有驅動**（`ubuntu-drivers autoinstall`），確認 `nvidia-smi` 正常
2. 依 Docker 官方文件安裝原生 Docker Engine（`docker-ce`、`docker-compose-plugin`），`sudo usermod -aG docker $USER` 後重新登入
3. 安裝 **NVIDIA Container Toolkit**，`sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`
4. 允許本機容器使用 X 顯示：`xhost +local:docker`（每次登入後執行，或寫進啟動腳本）
5. `git config --global core.autocrlf input`（Linux 預設即可，此設定為保險）

### 6.2 取得專案

目前 repo **沒有遠端**。二選一：
- 推到 GitHub 等遠端後在 Ubuntu `git clone`（建議）
- 或在 Ubuntu 掛載 Windows 的 D 槽，把整個資料夾（含 `.git`）複製到 Ubuntu 家目錄。**不要直接在 NTFS 分割區上開發**（權限與效能問題）

### 6.3 規劃與程式調整（新開 OpenSpec 修改或直接修改 `add-sim-environment`）

- `openspec/config.yaml` context、proposal、design、`specs/sim-runtime`：把「Windows 11 → WSL2 → WSLg」改為「Ubuntu 22.04 實機 + 原生 Docker」
- 刪除 `docker/compose.gpu-wsl.yaml` 與 `docs/環境設定.md`（WSL 專用），改寫 Ubuntu 版環境設定文件
- 新增 `docker/compose.gpu-nvidia.yaml`（`deploy.resources.reservations.devices` 指定 nvidia GPU、`NVIDIA_DRIVER_CAPABILITIES=all`、`LIBGL_ALWAYS_SOFTWARE=0`、移除 `MESA_GL_VERSION_OVERRIDE`），取代 task 1.4；驗證 `glxinfo -B` renderer 為 NVIDIA
- 第一次啟動前：`docker compose build sim`；`ros_ws/build`、`install`、`log` 不要從 Windows 帶過去（`.gitignore` 已排除），讓容器重新 `colcon build`（或 `BUILD=1`）

## 7. 常用指令

```bash
docker compose build sim                     # 建置映像
docker compose up sim                        # 啟動模擬（Gazebo GUI）
WORLD=warehouse_small_edited docker compose up sim
docker compose run --rm sim bash             # 進容器
BUILD=1 docker compose run --rm sim bash     # 強制重新 colcon build

# 容器內
ros2 run amr_worlds gen_world /ros_ws/src/amr_worlds/scenes/warehouse_small.yaml
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r cmd_vel:=/amr1/cmd_vel
cd /ros_ws/src/amr_worlds && python3 -m pytest -q test
cd /ros_ws/src/amr_bringup && python3 -m pytest -q test
```
