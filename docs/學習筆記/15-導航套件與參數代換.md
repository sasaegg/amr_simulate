# 15 導航套件、參數代換與執行資料目錄

檔案：[`amr_navigation/package.xml`](../../ros_ws/src/amr_navigation/package.xml)、[`setup.py`](../../ros_ws/src/amr_navigation/setup.py)、[`test_package_boundary.py`](../../ros_ws/src/amr_navigation/test/test_package_boundary.py)、[`compose.yaml`](../../docker/amr_sim/compose.yaml)

子專案 2（OpenSpec change `add-navigation`）task 1.1–1.3。

## 為什麼要做

- **獨立套件**：建圖、導航是車子系統的功能，真車上也會跑，但和中控 `amr_bringup`（負責帶起驅動）是不同職責。拆成 `amr_navigation`：依賴清楚（只有 slam_toolbox、Nav2），參數和 launch 有固定位置，邊界可以用測試守住。
- **先驗證參數代換**：Nav2 的參數檔要寫 frame 名稱（`amr1/base_footprint`），而 XML launch 不能像 Python 那樣改寫 YAML。如果代換行不通，後面所有參數檔都要換寫法，所以風險最高的先做。
- **執行資料目錄**：地圖是執行時產生的資料，不是原始碼，放在 `data/` 掛載到 robot 容器的 `/data`，存完就能用，不用 build。

## 做了什麼

### 1. 套件骨架（task 1.1）

```
amr_navigation/
  package.xml   exec_depend：slam_toolbox、nav2_*（13 個）、launch_xml
  setup.py      安裝 launch/*.launch.xml、config/*.yaml、config/*.rviz
  test/test_package_boundary.py
```

- Nav2 是很多個套件組成的，package.xml 依功能分組列出：定位（map_server、amcl、lifecycle_manager）、導航（planner、navfn、controller、dwb、smoother、behaviors、bt_navigator、waypoint_follower、velocity_smoother）。也可以只寫 `navigation2` 這個總套件，但會把用不到的東西都拉進來，也看不出實際用了哪些。
- 邊界測試和 `amr_bringup` 同一個概念：package.xml 不能列 `ros_gz*`、`amr_hw_sim`、`amr_worlds`；launch 和參數檔的內容裡也不能出現這些名稱（避免用 `$(find-pkg-share amr_hw_sim)` 偷偷繞過）。

### 2. 參數檔裡代換 robot_id（task 1.2）

Nav2 的節點**不是每個都是獨立程序**。planner_server 程序裡會再建一個 costmap 子節點，完整名稱是：

```
/amr1/planner_server                    ← 程序本身
/amr1/global_costmap/global_costmap     ← 程序內的子節點
```

ROS 2 的參數檔以「節點完整名稱」當鍵，參數才會套到對的節點上。所以參數檔寫成：

```yaml
/$(var robot_id)/global_costmap/global_costmap:
  ros__parameters:
    robot_base_frame: $(var robot_id)/base_footprint
```

launch 載入時加上 `allow_substs="true"`，`$(var robot_id)` 就會被代換：

```xml
<param from="$(find-pkg-share amr_navigation)/config/nav2.yaml" allow_substs="true"/>
```

官方 Nav2 是用 Python 的 `RewrittenYaml` 做同一件事；我們用 XML 的 `allow_substs`，效果相同。

### 3. 執行資料目錄（task 1.3）

```yaml
robot:
  volumes:
    - ../../data:/data       # 執行資料（地圖）：可寫，只有車子系統需要
```

`data/maps/` 納入 git（`.gitkeep` 讓空資料夾也能 commit；`.pgm` 已在 `.gitattributes` 標為 binary）。

## 怎麼驗證（2026-10-08 實測）

```bash
colcon build --symlink-install --packages-select amr_navigation
ros2 pkg prefix amr_navigation                       # /ros_ws/install/amr_navigation
env -i PATH=/usr/bin:/bin python3 -m pytest -q test  # 3 passed（不需要 ROS）
```

參數代換：最小 launch 只啟動 planner_server，**刻意用 `robot_id:=amr7`**，證明值是代換來的而不是寫死的：

```bash
ros2 lifecycle set /amr7/planner_server configure
ros2 param get /amr7/global_costmap/global_costmap robot_base_frame   # amr7/base_footprint
ros2 param get /amr7/global_costmap/global_costmap global_frame       # amr7/odom
```

對照組（拿掉 `allow_substs`）：節點一啟動就崩潰——`Couldn't parse params file ... namespace must not contain characters other than alphanumerics`。代表沒代換時 `$(var ...)` 會原封不動交給 rcl。

執行資料目錄：robot 容器 `touch /data/maps/test` → 主機 `data/maps/test` 擁有者是 `myuser`（容器使用者和主機同 UID，筆記 04）；sim 容器沒有 `/data`。

## 面試追問

**Q：Nav2 的 costmap 參數為什麼要寫成 `global_costmap: global_costmap:` 兩層？**
A：costmap 是 planner_server／controller_server 程序內建立的子節點，namespace 是 `global_costmap`、節點名稱也是 `global_costmap`，完整名稱 `/<ns>/global_costmap/global_costmap`。參數檔以節點完整名稱比對，所以要寫兩層。

**Q：多台車怎麼共用同一份 Nav2 參數檔？**
A：把車輛相關的部分（namespace、frame 前綴）換成變數，在 launch 時代換：Python 用 `RewrittenYaml`，XML 用 `<param from=... allow_substs="true"/>`。

**Q：lifecycle node 是什麼？為什麼要先 `configure` 才看得到參數？**
A：Nav2 的節點是 managed node，有 unconfigured → inactive → active 幾個狀態。configure 時才讀參數、建立 costmap 等資源，activate 時才開始運作。這讓系統能依序、可控地啟動（之後的 lifecycle_manager 負責自動做這件事，筆記 19）。

**Q：程式產生的資料（地圖）和原始碼為什麼要分開放？**
A：原始碼要 build 後才會安裝到 install 目錄；資料是執行中寫入的，放在原始碼裡會變成「程式在改自己的原始碼」，而且每次新增都要 build。分開後資料可以獨立掛載、備份，之後後端容器也能掛同一個資料夾。
