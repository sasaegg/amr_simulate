# 25 標地圖原點

檔案：[`map_origin.py`](../../ros_ws/src/amr_navigation/amr_navigation/map_origin.py)、[`map_origin_server.py`](../../ros_ws/src/amr_navigation/amr_navigation/map_origin_server.py)、[`SetMapOrigin.srv`](../../ros_ws/src/amr_interfaces/srv/SetMapOrigin.srv)、[`map_origin_panel.cpp`](../../ros_ws/src/amr_rviz_plugins/src/map_origin_panel.cpp)、[`set_origin_tool.cpp`](../../ros_ws/src/amr_rviz_plugins/src/set_origin_tool.cpp)、[`map_origin_ui.launch.xml`](../../ros_ws/src/amr_rviz_plugins/launch/map_origin_ui.launch.xml)

OpenSpec change `add-map-origin`（使用者要求，2026-10-08）。

## 為什麼要做

slam_toolbox 以「開始建圖時車的位置」當 `map` 座標系的原點。原本的處理是定一條慣例：「一律從出生點 (1, 1) 開始建圖，世界座標 = 地圖座標 + (1, 1)」。使用者指出這很怪：**掃圖時不應該預設知道出生點**。實際倉庫裡，車可能從任何地方開始掃；而且換個起點重掃，整張地圖的座標就全變了，之後標的儲位全部對不上。

正確的做法：掃完後，把原點**手動標在倉庫的固定參考點**（例如左下角、x 軸沿著南牆）。地圖座標就變成「倉庫座標」，和車從哪裡出發無關。

## 做了什麼

### 1. 座標轉換（`map_origin.py`）

選取的位姿 P = (px, py, θ) 以目前的地圖座標表示。任一點 q 的新座標：

```
q' = R(−θ) · (q − P)
```

先平移（P 變成 (0, 0)），再轉 −θ（θ 方向變成 +x）。

`.yaml` 的 `origin` 是**圖片左下角**在地圖座標的位置。新的 origin＝原圖四個角轉換後的最小 x、最小 y。

Nav2 會讀 origin 的角度，但 costmap、AMCL 等多數元件忽略它——所以**不能靠改 origin 角度轉向**，要轉就得把圖片本身轉正，origin 角度一律寫 0。

三種情況：

| 角度 | 圖片怎麼處理 | 失真 |
|---|---|---|
| 0° | 不動，只改 origin | 無 |
| 90° 倍數 | `numpy.rot90`：陣列整格旋轉 | 無（格數完全相同） |
| 其他 | 最近鄰重新取樣：新圖每一格的中心反推回舊圖，取最近的格子；外面補「未知」 | 斜邊會有鋸齒 |

**重新取樣的坑**：最近鄰是「新格子去找舊格子」，可能剛好**跳過某些舊格子**。測試發現：一格寬的牆轉 30° 後**消失了**。導航上「牆有缺口」比「牆多一格」危險得多，所以取樣後再把每一個舊的佔據格中心轉過去、標成佔據——障礙物寧多勿漏。

### 2. 「對齊 90° 倍數」（預設開啟）

滑鼠拖出來的方向不可能剛好 0°（實測拖了 −1.1°）。照實際角度轉，幾乎是正的地圖也會被重新取樣、反而變斜。面板預設把角度取最近的 0／90／180／270°，並顯示「拖曳 −1.1° → 套用 0.0°」。只有整張圖真的歪了才關掉。

### 3. 檔案安全

- **原子寫入**：新內容先寫到同資料夾的暫存檔（`mkstemp`），全部寫好才 `os.replace` 換上——失敗時原檔不變（和 `gen_world` 同一套）。
- **備份**：改寫前把原檔複製成 `<名稱>.bak.pgm`／`.bak.yaml`（只保留最近一次，`.gitignore` 排除）。
- **名稱白名單**：只接受英數字、`_`、`-`，`../etc` 這種直接拒絕，不讀寫任何檔案。

### 4. 自訂 ROS 介面（`amr_interfaces`）

ROS 內建的服務型別沒有「地圖名稱＋x、y、角度」這種組合，所以自己定義：

```
# srv/SetMapOrigin.srv
string map_name
float64 x
float64 y
float64 yaw
---
bool success
string message
```

自訂介面要放在**獨立的 ament_cmake 套件**：

```cmake
find_package(rosidl_default_generators REQUIRED)
rosidl_generate_interfaces(${PROJECT_NAME} "srv/SetMapOrigin.srv")
```

package.xml 要有 `rosidl_default_generators`（build）、`rosidl_default_runtime`（exec）、`<member_of_group>rosidl_interface_packages</member_of_group>`。build 時 rosidl 產生 C++ 標頭（`amr_interfaces/srv/set_map_origin.hpp`）和 Python 模組（`from amr_interfaces.srv import SetMapOrigin`），兩邊都能用。

### 5. 服務節點與 UI

- `map_origin_server`（`amr_navigation`）：`/map_origin/set`，呼叫 `map_origin.py`。地圖在車上，所以服務在車上；面板在哪台電腦都只是呼叫服務（同存圖面板的設計）。
- `map_origin_ui.launch.xml`：顯示用 map_server（名稱 `/map_origin_viewer`、topic `/map_origin/map`，和導航用的分開）＋ 改寫服務 ＋ RViz。不需要世界與車子系統。
- **不帶車輛 namespace**：地圖原點是倉庫的屬性、和哪一台車無關（使用者驗收時指出面板不該有「車輛」欄位）。所以服務、topic 都是 `/map_origin/...`，面板沒有車輛欄位，launch 沒有 `robot_id`。
- 「設定原點」工具：**繼承 RViz 的 GoalTool**（2D Goal Pose），只改名稱、topic 由設定檔指定。按下＝位置、拖曳＝方向，和導航點目標的手感一樣，但不會看到「2D Goal Pose」而誤以為是導航。
- 面板：從 map_server 的 `get_parameters` 服務讀 `yaml_filename` 得知要改哪張地圖（不讓人手打）；套用成功後呼叫 map_server 的 `load_map` 重新載入，並發布 (0, 0, 0) 讓預覽座標軸移到新原點。

### 6. repo 地圖的轉換

模擬倉庫的左下角在原本的地圖座標 (−1, −1)。用同一個服務輸入精確值 (−1, −1, 0)（不是手點，因為冒煙測試要拿它和 Gazebo 真實位置比對）：只有 `.yaml` 的 origin 從 (−1.13, −1.11) 變成 (−0.13, −0.11)，`.pgm` 一個位元組都沒變。之後**地圖座標 = Gazebo 世界座標**，導航冒煙測試直接用世界座標（初始位姿 (1, 1, 0)、目標 (10, 1)、箱子 (7, 4)），「+ (1, 1)」的換算全部拿掉。

## 面試追問

**Q：地圖座標系的原點應該怎麼定？**
A：SLAM 只能以起點當原點，所以建完圖要定義「場地座標」：把原點和方向對齊到場地的固定參考（牆角、柱子、充電站）。這樣重建地圖、多台車、儲位與派車都用同一套座標。

**Q：地圖要轉向時，為什麼不改 yaml origin 的角度就好？**
A：Nav2 多數元件（costmap、AMCL）忽略 origin 的角度，佔據格地圖被當成和座標軸對齊的網格。要轉向就得把圖片本身轉正：90° 倍數用陣列旋轉（無損），其他角度要重新取樣。

**Q：重新取樣佔據格地圖要注意什麼？**
A：最近鄰可能跳過細小的障礙物（一格寬的牆會斷掉），對導航很危險；要保守處理——確保原本的佔據格在新地圖仍是佔據。另外只能出現佔據／空曠／未知三種值，不能用會產生中間值的雙線性內插。

**Q：ROS 2 怎麼自訂服務？**
A：獨立的 ament_cmake 套件，`.srv` 放在 `srv/`，CMake 用 `rosidl_generate_interfaces`，package.xml 加 rosidl 的相依與 `rosidl_interface_packages` 群組；build 後 C++ 和 Python 都能用。

**Q：改寫使用者的資料檔，怎麼避免改壞？**
A：輸入白名單、先寫暫存檔再原子換上、改寫前備份、任何失敗都不動原檔，並用測試驗證「失敗時原檔逐位元組不變」。

## 踩坑紀錄

- **測試把牆放在地圖外**：地圖寬 20 格 × 0.1 m，x 範圍 −1.0～1.0（不含 1.0），牆放在 x = 1.0 剛好出界。是測試寫錯，移到 0.5。
- **最近鄰把一格寬的牆吃掉**：見上面，取樣後補回舊佔據格。
- **服務回呼命名為 `handle`，節點一建立就崩潰**（`AttributeError: __enter__`）：rclpy 的 `Node` 有一個 `handle` 屬性（底層 C 節點物件），被同名方法蓋掉。改名 `on_set_origin`。
- **面板一直等不到地圖名稱、套用永遠是灰的**：RViz 先呼叫面板的 `onInitialize()` 再 `load()`；兩個地方都重建連線，第二次把第一次送出的請求連同客戶端丟掉，回呼不會執行，「忙碌中」旗標就卡在 true。一度以為是 `AsyncParametersClient` 的問題（換成一般服務客戶端也一樣）——看除錯訊息「第一次 busy=0、之後永遠 busy=1」才找到真正原因。改成 `load()` 只在車輛 id 變了才重建，重建時忙碌旗標歸零；建圖面板一併修正。
- **套用後預覽座標軸留在舊座標**：原點變了，舊的選取位置看起來浮在地圖外。套用成功後發布 (0, 0, 0)，預覽移到新原點。
- **面板一開始有「車輛」欄位、名稱都在 `/amr1/` 下**：照存圖面板的寫法照抄，沒想到地圖原點和車無關。使用者驗收時指出，改成不帶 namespace。
- **測試環境殘留多組 UI，一次套用被執行兩次**：用 `pkill -f "ros2 launch"` 重啟 UI 時子程序沒跟著結束，同名服務有多個伺服器，一次呼叫被每個都執行。這也提醒使用上**同時只能開一個地圖原點 UI**（README 有寫）。
