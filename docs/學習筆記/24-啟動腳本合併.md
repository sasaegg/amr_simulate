# 24 啟動腳本合併（up.sh）

檔案：[`docker/amr_sim/up.sh`](../../docker/amr_sim/up.sh)、[`compose.software.yaml`](../../docker/amr_sim/compose.software.yaml)

OpenSpec change `unify-up-script`（使用者要求，2026-10-08）。

## 為什麼要做

原本 `up_gpu.sh`、`up_cpu.sh` 兩個腳本只差一個 `-f compose.software.yaml`，而且一律啟動兩個容器。合併成一個 `up.sh`，用參數決定繪圖方式與目標容器——例如只想讓 robot 改用 CPU 排查 RViz 問題，不必連 Gazebo 一起重開。

## 做了什麼

```bash
up.sh <gpu|cpu> <sim|robot|all> [其餘參數交給 docker compose up]
```

```bash
[ $# -ge 2 ] || usage                     # 參數不夠就顯示用法

case "$1" in                              # 繪圖方式
    gpu) files=(-f compose.yaml) ;;
    cpu) files=(-f compose.yaml -f compose.software.yaml) ;;
    *) usage ;;
esac

case "$2" in                              # 目標容器
    sim|robot) services=("$2") ;;
    all) services=() ;;
    *) usage ;;
esac

shift 2                                   # 丟掉前兩個參數，剩下的（例如 --build）交給 compose
exec docker compose "${files[@]}" up -d "$@" "${services[@]}"
```

逐段說明：
- **`$#`**：參數個數；`$1`、`$2`：第一、第二個參數。
- **`case ... esac`**：比對字串，`sim|robot)` 是「sim 或 robot」；`*)` 是其他所有情況。比 if/elif 清楚，打錯字直接進 `usage`。
- **bash 陣列 `files=(...)`、`"${files[@]}"`**：每個元素保持是一個獨立參數（含空白也不會被拆開）；空陣列展開成「什麼都沒有」——`all` 時就不傳服務名稱。
- **`shift 2`**：把 `$1`、`$2` 移掉，`"$@"` 變成剩下的參數。
- **`exec`**：用 docker compose 取代目前的 shell 程序（不多留一層 bash），結束碼直接就是 compose 的。
- **`usage` 裡 `exit 2`**：shell 慣例，2 代表「用法錯誤」；檢查都在呼叫 compose 之前，保證打錯時什麼都不會動。
- **兩個參數都必填、不給預設**：和 `exec.sh` 同一個原則——預設值會讓人沒注意就開錯模式或重建到另一個容器。

compose 的兩個機制：
- **`-f` 疊加**：後面的檔案覆寫前面的（`compose.software.yaml` 把 GPU 裝置 `!reset` 掉、改用 mesa）。
- **指定服務名稱**：`docker compose up -d robot` 只建立／重建 robot；同一個 compose 專案裡的 sim 不受影響。所以可以 sim 用 GPU、robot 用 CPU。設定沒變的服務 compose 不會重建（`Running`），設定變了才重建（`Started`）。

## 怎麼驗證（2026-10-08 實測）

| 指令 | 結果 |
|---|---|
| `up.sh`、`up.sh gpu`、`up.sh foo all`、`up.sh gpu foo` | 顯示用法、結束碼 2，容器 ID 都沒變 |
| `up.sh gpu all`（已經是 GPU） | 兩個都 `Running`，沒有重建 |
| `up.sh cpu robot` | 只有 robot 重建，renderer 變 llvmpipe；sim 容器 ID 不變、仍是 nvidia |
| `up.sh gpu robot` | robot 改回 RTX 3060，sim 仍未重建 |
| `up.sh gpu sim --build` | `--build` 有傳給 compose（映像重新建置，全部命中快取） |
| `up.sh cpu all` → `up.sh gpu all` | 兩個都 llvmpipe → 兩個都 RTX 3060 |

## 面試追問

**Q：shell 腳本怎麼處理參數比較穩？**
A：先檢查參數個數與合法值，錯了就印用法、以非零碼（慣例 2）結束，而且要在做任何事之前檢查完；用 `case` 比對；要轉交的參數用 `"$@"`、陣列用 `"${arr[@]}"`，加引號避免被空白拆開；腳本開頭 `set -euo pipefail`。

**Q：`exec` 在腳本最後一行的作用？**
A：用新程式取代 shell 本身，不多一層程序；訊號（Ctrl+C）直接送到該程式，結束碼也直接傳回。

**Q：docker compose 怎麼只重啟其中一個服務？怎麼切換不同設定？**
A：`docker compose up -d <服務>` 只處理指定服務；用多個 `-f` 疊加覆寫檔切換設定（例如 GPU／軟體渲染），compose 比對設定，不同才重建。

## 踩坑紀錄

- **測試結束碼得到 141**：`up.sh ... | head -1` 讀完第一行就關閉管線，腳本寫下一行時收到 SIGPIPE（128 + 13 = 141）。測結束碼時不要接 `head`。
