## 為什麼要做

建圖和導航都能單獨啟動了，但正式使用時希望「一行指令把整台車帶起來」——這就是中控 `robot.launch.xml` 的角色（子專案 1 的設計：中控依 `hardware` 帶起驅動）。這次再加一個維度 `mode`，決定要同時帶起哪個功能。兩種方式都保留，各有用途：

| 方式 | 優點 | 缺點 |
|---|---|---|
| `robot.launch.xml mode:=navigation` | 一行；`use_sim_time` 自動依 hardware 決定 | 換模式要重啟整個車子系統（模擬時車被移回出生點） |
| 另外啟動 `mapping.launch.xml`／`navigation.launch.xml` | 驅動不重啟，車留在原地；建完圖直接切導航 | 要多開終端機、自己加 `use_sim_time:=true` |

## 做了什麼

```xml
<arg name="mode" default="none" description="none、mapping 或 navigation"/>
<arg name="map" default="warehouse_small" .../>

<let name="is_mapping" value="$(equals $(var mode) mapping)"/>
<let name="is_navigation" value="$(equals $(var mode) navigation)"/>
<let name="mode_ok" value="$(or $(equals $(var mode) none) $(or $(var is_mapping) $(var is_navigation)))"/>
<let name="run" value="$(and $(var is_sim) $(var mode_ok))"/>

<group unless="$(var mode_ok)">
  <log message="mode 必須是 none、mapping 或 navigation，收到 '$(var mode)'"/>
  <shutdown reason="mode 不正確"/>
</group>

<group if="$(var run)">
  ...robot_state_publisher、虛擬驅動...
  <include file="$(find-pkg-share amr_navigation)/launch/mapping.launch.xml" if="$(var is_mapping)">
    <arg name="use_sim_time" value="$(var is_sim)"/> ...
  </include>
  <include file="$(find-pkg-share amr_navigation)/launch/navigation.launch.xml" if="$(var is_navigation)"> ... </include>
</group>
```

- **`$(or a b)` 只接受兩個參數**，三選一要巢狀寫。
- **`run` = hardware 是 sim 且 mode 合法**：原本節點的 group 只看 `is_sim`，mode 打錯時 `<shutdown>` 前節點已經開始啟動。改成全部檢查通過才進 group（和 hardware 的處理一致：不合法就什麼都不啟動）。
- `use_sim_time:=$(var is_sim)`：由 hardware 決定，不給使用者另一個可能矛盾的開關。
- `amr_bringup` 的 package.xml 加 `amr_navigation`：它也是車子系統的一部分（真車會裝），可以宣告相依；模擬套件 `amr_hw_sim` 仍然不能。邊界測試改為檢查「模擬套件只出現在 `if="$(var run)"` 的 group 內，且 `run` 包含 `is_sim`」。

## 面試追問

**Q：一個機器人的 bringup 要怎麼組織？**
A：中控 launch 依參數組合各層：共用節點（robot_state_publisher）、驅動（依硬體模式：模擬或真車）、功能（依任務模式：建圖或導航）。各層是獨立的 launch 檔，可以單獨啟動測試；中控只負責「帶起哪些」，不放細節。

**Q：launch 參數不合法時怎麼處理比較好？**
A：在任何節點啟動前檢查並明確結束，訊息說明收到的值與可用值。半套啟動（有些節點起來了、有些沒有）最難排查。XML 用 `<let>` 算條件、`<group if>` 包住所有節點、`<shutdown>` 結束。

**Q：建圖完要切導航，為什麼不重啟整個系統？**
A：重啟會讓驅動重來（模擬時車被移回出生點；真車上則是重新初始化硬體），也會讓 odom 歸零。只換上層的功能，車留在原地，接著在 RViz 給初始位姿就能導航。

## 踩坑紀錄

- **mode 打錯時節點還是啟動了**：group 原本只看 `is_sim`；改用 `run`（is_sim 且 mode 合法）。
- **用 `pgrep -f` 比對 PID 時抓到自己**：`bash -c 'pgrep -f "A|B"'` 的命令列本身包含樣式字串，會被算進去；比對時只看真正的節點程序。
