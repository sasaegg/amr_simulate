# 12 冒煙測試（launch_testing）

檔案：[`ros_ws/src/amr_hw_sim/test/test_sim_smoke.py`](../../ros_ws/src/amr_hw_sim/test/test_sim_smoke.py)

## 為什麼要做

單元測試只驗證各零件；冒煙測試把整個系統（世界 + 車子系統 + 虛擬驅動）真的跑起來，檢查資料路徑是否接通、spec 中可自動化的情境是否成立。之後每次修改都能一個指令確認「整台車還活著」——冒煙測試的名字來自「通電後沒冒煙就算過第一關」。

## 做了什麼

### 測試放在 amr_hw_sim

它需要同時啟動世界與車子系統（hardware: sim）。放在 `amr_bringup` 會讓車子系統依賴模擬套件，違反套件邊界；`amr_hw_sim` 本來就是模擬側，依賴 `amr_bringup`、`amr_worlds` 沒問題（方向是「模擬依賴車子系統」，不是反過來）。

### launch_testing 的結構

```python
@pytest.mark.launch_test
def generate_test_description():          # 1. 啟動被測系統
    return LaunchDescription([
        include('amr_worlds', 'world.launch.py', world=WORLD, headless='true'),
        TimerAction(period=3.0, actions=[include('amr_bringup', 'robot.launch.py', config=...)]),
        launch_testing.actions.ReadyToTest(),   # 告訴框架：可以開始跑測試了
    ])

class TestSimSmoke(unittest.TestCase):    # 2. 系統執行中跑的測試
    def test_01_...(self): ...

@launch_testing.post_shutdown_test()
class TestShutdown(unittest.TestCase):    # 3. 系統關閉後的檢查
    def test_processes_exit_cleanly(self, proc_info):
        launch_testing.asserts.assertExitCodes(proc_info, allowable_exit_codes=[0, -2, 2, 130])
```

- 測試在**一個**啟動的系統上依序執行；unittest 依**方法名稱排序**，所以用編號控制順序：光達幾何要在車子移動之前、暫停 `/clock` 放最後。
- 測試自己建立一個 rclpy 節點訂閱 scan／odom／clock，用 `spin_until(條件, timeout)` 等待資料（不用 `sleep` 猜時間）。
- 出生點由測試寫一份暫存的 `robot.yaml` 傳給 `robot.launch.py`——走跟使用者完全相同的設定路徑。
- `pytest.importorskip('launch_testing')`：沒有 ROS 的環境（`env -i` 跑純邏輯測試）整個檔案略過而不是失敗。

### headless 與 EGL

`world.launch.py headless:=true` → `ign gazebo -s --headless-rendering`：
- `-s`：只跑 server，不開 GUI（不需要 X 顯示）。
- `--headless-rendering`：用 **EGL** 在沒有視窗的情況下建立 OpenGL 環境做離屏渲染。gpu_lidar 需要渲染深度影像，所以不開 GUI 也要能渲染——EGL 讓它在 CI 這類沒有螢幕的機器上也能跑（仍需 GPU，或改用軟體渲染）。

## 面試追問

**Q：單元測試、整合測試、冒煙測試差在哪？**
A：單元測試驗證單一函式或類別（快、不需環境）；整合測試驗證元件之間的互動；冒煙測試是最粗的整合測試，確認整個系統能啟動、主要功能沒壞，通常放在 CI 最前面當守門。

**Q：ROS 2 怎麼寫系統層級的自動測試？**
A：launch_testing：`generate_test_description` 啟動被測的 launch，`ReadyToTest` 後執行 unittest 測試（可以建立節點訂閱、發布、查 TF），`post_shutdown_test` 在關閉後檢查結束碼。colcon test 會透過 pytest 外掛執行它。

**Q：在沒有螢幕的 CI 上怎麼跑需要渲染的模擬？**
A：Gazebo 只跑 server（`-s`），用 `--headless-rendering`（EGL）做離屏渲染；機器沒有 GPU 時改用軟體渲染（llvmpipe）。

**Q：測試怎麼避免「時好時壞」（flaky）？**
A：不用固定的 sleep 猜時間，用「輪詢條件直到成立或逾時」；依賴的先後順序明確（編號）；用跟使用者相同的設定路徑啟動；時間門檻留合理餘裕（停車 0.86 s vs 1 s）。

## 踩坑紀錄

- **pytest 只顯示一個 `test_sim_smoke PASSED`**：launch_testing 的 pytest 外掛把整個 launch 測試合併成一項；要看每個方法的結果用 `launch_test <檔案>`。
- **刪除原始檔後 colcon build 失敗**（`can't copy .../warehouse_small_edited.sdf`）：`--symlink-install` 在 `build/` 留下指向已刪除檔案的 symlink，`glob` 還會找到它。刪除原始檔後要清掉該套件的 `build/` 與 `install/` 重建。
- `colcon test-result` 讀的是 `build/` 裡現有的報告；先刪舊報告再跑，避免看到過期的結果。
